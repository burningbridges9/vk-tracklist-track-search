# VK Tracklist Search — что сделали и как ищем треки

Дата: 2026-10-17. Версия расширения: **1.1.0**. Автотесты: **47/47** (jsdom).

> Этот файл можно приложить к новой сессии как контекст: в нём есть постановка задачи, разметка VK, алгоритм поиска и подводные камни.

## Коротко

- Задача: в постах `vk.ru` находить треклисты и давать открыть поиск каждого трека в аудио VK.
- Решение: content script находит `[data-testid="post_text"]`, разбирает текст на строки, распознаёт строки «исполнитель — название» и вставляет в конец строки кнопку с лупой.
- Кнопка ведёт на `https://vk.ru/audios<ID>?q=<запрос>`, где `q` закодирован **дважды** (`%2520` вместо `%20`), потому что VK сам декодирует его дважды.
- Обязательное условие по умолчанию: в посте есть **аудио или видео**. Иначе кнопок нет.
- Поддерживаются нумерованные треклисты (`04 Grum - Stay With Me`) и без номеров — если есть заголовок `Tracklist:` / `Треклист:` / `Playlist:` либо блок из 5+ строк подряд.
- Название выпуска до заголовка (например, `Elias Erium - The Outer Experience 063 ...`) треком не считается.

Исходные посты, на которых всё проверялось:

1. ASOT 1299 — 37 нумерованных треков, в посте прикреплён аудио-трек (эпизод).
2. Elias Erium — 25 треков без номеров, с заголовком `Tracklist:`.

## 1. Проблема

В постах VK паблики публикуют треклисты радиошоу. Строки выглядят так:

```text
01 GXD & Elle Vee - Sail (Ginchy Remix)
02 Beatsole - Awaking
...
04 Grum - Stay With Me
```

Нужно, чтобы у каждой строки была кнопка (или кликабельная строка), открывающая страницу поиска VK с уже подставленным запросом. Для строки `04 Grum - Stay With Me` целевой адрес:

```text
https://vk.ru/audios123456789?q=Grum%2520-%2520Stay%2520With%2520Me
```

Число `123456789` — ID владельца аудио (в примере — ID пользователя). В расширении он **не захардкожен**: определяется автоматически или задаётся в настройках.

Требования, которые обсуждались:

- кнопка рядом со строкой либо кликабельная строка;
- обязательное условие — в посте есть аудио или видео (чтобы не превращать в поиск случайные нумерованные списки);
- треклист определяется эвристически, потому что разметка поста — просто текст;
- работает в ленте, в модалках и после SPA-переходов без перезагрузки.

## 2. Что сделано

Расширение Chrome Manifest V3. Устанавливается как unpacked, работает на `https://vk.ru/*` и `https://vk.com/*`.

Что видит пользователь:

- в конце каждой строки треклиста появляется маленькая кнопка с лупой;
- обычный клик открывает поиск в новой вкладке (настраивается);
- Ctrl+клик и средний клик работают как у обычной ссылки;
- кнопка не мешает выделять и копировать текст поста;
- при повторной отрисовке поста кнопки восстанавливаются, дубликатов нет.

Файлы:

```text
extension/
  manifest.json
  common.js           настройки по умолчанию
  content.js          вся логика: разбор поста и кнопки
  content.css         стиль кнопки
  background.js       клик по иконке открывает настройки
  options.html/css/js страница настроек
  icons/              иконки 16/32/48/128
test/
  fixture.html        макет постов VK
  run-tests.mjs       тесты на jsdom
tools/
  build.ps1           сборка dist/ и ZIP
  make_icons.py       генерация иконок
dist/
  vk-tracklist-search-1.1.0.zip
```

Настройки хранятся в `chrome.storage.sync`:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | Расширение включено. |
| `requireMedia` | `true` | Только посты с аудио/видео. |
| `minTracks` | `3` | Минимум строк для треклиста. |
| `openInNewTab` | `true` | Открывать поиск в новой вкладке. |
| `queryEncoding` | `double` | Двойное кодирование `q` (как у VK). |
| `audioOwnerId` | `''` | Ручной ID владельца аудио. |

В `chrome.storage.local` лежат:

- `detectedAudioOwnerId` — ID, подсмотренный в адресе `/audios<ID>`;
- `pendingAudioSearch` — отложенный запрос на случай, если VK потеряет `q` при редиректе (см. раздел 6).

## 3. Разметка поста VK

Упрощённо реальный пост выглядит так:

```html
<div data-testid="post" data-post-id="-22744062_1292261">
  <div data-testid="post-content-container">
    ...
    <span data-testid="post_text" data-post-id="-22744062_1292261" id="text-3">
      <div data-testid="showmoretext">
        <div data-testid="showmoretext-in-expanded">
          <div class="vkit-0wZYbU">
            <a data-testid="post-text-mention" href="/club22744062">Armin van Buuren</a>
            – A State Of Trance 1299 (Guest Mix by MDDLTN) (15.10.2026)
            <div class="vkit-S4nqJ8" style="--...; width: 0px;"><br> </div>
            01 GXD &amp; Elle Vee - Sail (Ginchy Remix)<br>
            02 Beatsole - Awaking<br>
            ...
          </div>
        </div>
      </div>
    </span>
    <div data-testid="primary-attachment-photo">
      <div data-testid="music-track-overlay-badge">...</div>
    </div>
  </div>
</div>
```

Важные селекторы:

- контейнер поста — `[data-testid="post"]`;
- текст поста — `[data-testid="post_text"]` (в старых версиях встречается `post-text`);
- строки разделены `<br>`;
- пустые строки — это `div` шириной 0 с `<br>` внутри;
- музыкальное вложение — `data-testid`, содержащий `music` (`music-track-overlay-badge`, `musicattach-playbackcontrol` и т.п.);
- видео — `video` или `data-testid`, содержащий `video`.

### Главная ловушка

У самого `span[data-testid="post_text"]` тоже есть `data-post-id`. Если искать пост через `container.closest('[data-post-id]')`, вернётся **сам текстовый блок**, а не корень поста. Тогда поиск вложений внутри него ничего не найдёт и кнопки не появятся.

Правильно:

```js
function findPostRoot(container) {
  var post = container.closest('[data-testid="post"]');
  if (!post && container.parentElement) {
    post = container.parentElement.closest('[data-testid="post"], [data-post-id]');
  }
  return post;
}
```

## 4. Как текст превращается в строки

`extractLines(container)` рекурсивно обходит DOM текста и собирает строки. Логика:

- текстовый узел добавляется в текущий буфер;
- `<br>` завершает строку;
- блочные элементы (`DIV`, `P`, `LI`, `H1`–`H6`, `BLOCKQUOTE`, `PRE`, ...) — тоже границы строк;
- `<img>`, `<svg>`, `<video>`, `<audio>` пропускаются (эмодзи и иконки не должны попадать в запрос);
- `<button>`, `role="button"`, `aria-hidden="true"` пропускаются (кнопка «Показать полностью» не должна приклеиваться к последней строке);
- собственные кнопки расширения (`[data-vkt-search-btn]`) пропускаются;
- `&nbsp;` заменяется на пробел, все пробелы схлопываются, края обрезаются.

Для каждой строки сохраняются:

- `text` — нормализованный текст;
- `anchor` — элемент, **перед** которым вставить кнопку (обычно `<br>` в конце строки);
- `lastTextNode` — последний текстовый узел строки (нужен для последней строки, у которой нет `<br>`);
- `gapBefore` — начинается ли строка новый абзац (нужно для треклистов без номеров).

### Абзацный разделитель

Пустая строка VK — это `div` шириной 0:

```html
<div style="... width: 0px;"><br> </div>
```

Если вставить кнопку внутрь такого `div`, она окажется в блоке нулевой ширины и может быть не видна. Поэтому:

```js
function breakAnchor(br, container) {
  var parent = br.parentElement;
  if (parent && parent !== container && parent.tagName === 'DIV') {
    var style = parent.getAttribute('style') || '';
    var onlyBreak = !parent.textContent.trim() &&
      parent.querySelectorAll('br').length === 1 &&
      !parent.querySelector('a,img,svg');
    if (/width:\s*0(?:px)?/i.test(style) || onlyBreak) return parent;
  }
  return br;
}
```

То есть кнопка вставляется **перед** таким `div`, а не внутрь него. А `gapBefore = true` ставится следующей строке — это признак нового абзаца.

### Последняя строка

У последней строки поста нет завершающего `<br>`. Вставка `container.appendChild(button)` уехала бы на новую строку после блочных обёрток. Поэтому:

```js
function endInsertionPoint(lastTextNode, container) {
  // если строка закончилась ссылкой — вставляем после ссылки,
  // иначе сразу после последнего текстового узла
  ...
}
```

## 5. Распознавание треков

### 5.1. Нумерованные строки

Регулярное выражение:

```js
/^(?:\[\d{1,2}:\d{2}(?::\d{2})?\]\s*)?(\d{1,3})(?!\d)\s*[.)\]]?\s*(?:[-–—]\s+)?(.+)$/
```

Что оно умеет:

- `04 Grum - Stay With Me`
- `1. Artist – Title`
- `[00:12] 03 Artist - Title (Remix)`
- `01.Artist - Title`

Зачем `(?!\d)`: чтобы `2024 - итоги года` не превратилось в «трек 202». После номера обязательно должен быть разделитель/пробел, а не ещё одна цифра.

Дальше из остатка убирается ведущий дефис и ищется разделитель «исполнитель — название»:

```js
/^(.+?)\s+[-–—]\s+(.+)$/     // " - ", " – ", " — "
/^(.+?)\s*[–—]\s*(.+)$/      // en/em dash без пробелов
```

Требования:

- обе части непустые;
- в «исполнителе» есть хотя бы одна буква (`/\p{L}/u`), поэтому `2024 - 2025` не станет треком;
- запрос — это **весь остаток строки**, включая `(Original Mix)`, `(Remix)`, `feat. ...`. Например, `Grum - Stay With Me` или `KUKO - Voicemail (Tiësto Remix)`.

Строки-заголовки блоков (`Progressive Pick:`, `Tune Of The Week:`, `MDDLTN played:`) не проходят: в них нет разделителя « - ».

### 5.2. Строки без номеров

Пример:

```text
Elias Erium - The Outer Experience 063 (Live from Stereo, Part 2)

Tracklist:

Molac, Plecta - Zenith (Original Mix)
Tonecast - Radiance (Patch Park Edit)
...
```

Работают два режима.

**Режим заголовка.** Ищем строку-заголовок:

```js
/^(?:track\s*list|треклист|playlist|плейлист|tl)\b/i
```

(строка не длиннее 60 символов). Берём строки после **последнего** такого заголовка и собираем подряд идущие строки «исполнитель — название». Останавливаемся на первой строке, которая треком не является (после того как уже набрали хотя бы один трек). Порог — `minTracks` (по умолчанию 3).

Именно поэтому название выпуска `Elias Erium - The Outer Experience 063 ...` не получает кнопку: оно стоит **до** `Tracklist:`.

**Режим блока.** Если заголовка нет, ищем самый длинный непрерывный блок строк «исполнитель — название». Блок обрывается на не-трековой строке и на абзацном разрыве (`gapBefore`), чтобы название выпуска не приклеилось к треклисту. Порог — `max(minTracks, 5)`, то есть минимум 5 строк подряд.

Нумерованные треки имеют приоритет: если их набралось `minTracks`, берутся только они. Иначе сравниваются нумерованный и ненумерованный варианты, и выбирается тот, где треков больше.

### 5.3. Что треком не считается

- `Tracklist:`, `Progressive Pick:`, `Tune Of The Week:`, `MDDLTN played:`;
- название выпуска/поста;
- строки без разделителя (`Play It Loud (Keep It Going)`);
- URL (`https://...`);
- чисто числовые «исполнители» (`2024 - итоги года`);
- строки длиннее 300–400 символов (защита от абзацев прозы).

### 5.4. Порог

`minTracks` по умолчанию 3. Для блока без заголовка — не меньше 5. Это компромисс: не подсвечивать случайные списки, но ловить короткие треклисты.

## 6. Ссылка поиска

### Формат

```text
https://vk.ru/audios<ID>?q=<дважды URL-encoded запрос>
```

Пример для `Grum - Stay With Me`:

```text
encodeURIComponent("Grum - Stay With Me")
  => "Grum%20-%20Stay%20With%20Me"

encodeURIComponent(ещё раз)
  => "Grum%2520-%2520Stay%2520With%2520Me"

https://vk.ru/audios123456789?q=Grum%2520-%2520Stay%2520With%2520Me
```

Почему дважды: VK сам декодирует параметр поиска ещё раз, и в адресах, которые генерирует сайт, пробел выглядит как `%2520`. Если у пользователя поиск открывается, но в строке запроса видно `%20`, в настройках есть переключатель на обычное (одинарное) кодирование.

Код:

```js
function encodeQuery(query) {
  var once = encodeURIComponent(query);
  return settings.queryEncoding === 'single' ? once : encodeURIComponent(once);
}

function buildSearchUrl(query) {
  return location.origin + '/audios' + resolveOwnerId() + '?q=' + encodeQuery(query);
}
```

`location.origin` — чтобы остаться на `vk.com`, если пользователь там (на `vk.ru` будет `vk.ru`).

### ID владельца аудио

Приоритет:

1. `settings.audioOwnerId` — если пользователь вписал вручную;
2. число из текущего адреса `/audios<ID>` или `/audios/<ID>`;
3. `detectedAudioOwnerId` из `chrome.storage.local`.

ID учится только со страницы музыки (адрес `/audios<ID>`). Ссылки из ленты не используются: они могут вести на чужую музыку.

Если ID неизвестен, ссылка строится как `https://vk.ru/audios?q=...`. Когда вкладка открывает страницу музыки, content script запоминает ID из адреса и дальше подставляет его.

### Если VK теряет `q` при редиректе

На клик по кнопке без известного ID запрос сохраняется в `chrome.storage.local` как `pendingAudioSearch = { query, ts }`. Вкладка со страницей музыки читает его:

- если в адресе уже есть `?q=...` — запрос доехал, ничего не делаем;
- если адрес стал `/audios<ID>` без `q` — делаем `location.replace('/audios<ID>?q=...')`;
- если адрес так и остался `/audios` — ждём; при SPA-переходе на `/audios<ID>` сработает повторная проверка;
- запись живёт 2 минуты.

Это делает первый клик рабочим даже до того, как ID был определён.

## 7. Вставка кнопки

Кнопка — обычная ссылка, чтобы работали Ctrl/средний клик:

```html
<a class="vkt-track-search-btn"
   data-vkt-search-btn
   data-vkt-key="3"
   data-vkt-query="Grum - Stay With Me"
   href="https://vk.ru/audios123456789?q=Grum%2520-%2520Stay%2520With%2520Me"
   target="_blank" rel="noopener noreferrer"
   title="Найти «Grum - Stay With Me» в аудио VK">
  <svg>...</svg>
</a>
```

Правила вставки:

- вставляем **перед** `anchor` (обычно `<br>` в конце строки) — кнопка оказывается в конце строки;
- для последней строки — после `lastTextNode`;
- `data-vkt-key` — индекс трека в посте; по нему проверяем, не стоит ли уже кнопка, чтобы не дублировать;
- если текст поста изменился и запрос для этого индекса стал другим, старая кнопка удаляется и создаётся заново;
- если треков стало меньше, лишние кнопки удаляются.

События:

- `click` — `stopPropagation`, чтобы VK не перехватил клик; при `openInNewTab = false` — `preventDefault()` и переход в текущей вкладке;
- `mousedown` / `pointerdown` / `mouseup` — `stopPropagation`;
- `auxclick` (средняя кнопка) — сохраняем pending-запрос, если ID ещё нет.

CSS:

- `display: inline-flex !important`, 16×16, `vertical-align: -3px`, `margin-left: 4px`;
- прозрачный фон, цвет из `--vkui--color_icon_secondary` с fallback;
- `opacity: .55`, на hover — 1 и акцентный цвет;
- `user-select: none`, чтобы кнопка не попадала в выделение;
- `a.vkt-track-search-btn { text-decoration: none !important; }`.

## 8. Жизненный цикл страницы

- `MutationObserver` на `document.documentElement` (`childList`, `subtree`), сканирование с дебаунсом 250 мс.
- Скан ищет все `[data-testid="post_text"]` и обрабатывает каждый.
- Раз в секунду проверяется `location.href` для SPA-переходов. Если изменился только hash — ничего не делаем; если путь/query — убираем старые кнопки и сканируем заново.
- Изменения настроек (`chrome.storage.onChanged`) применяются сразу: кнопки удаляются, страница сканируется заново.
- При выключении расширения кнопки удаляются, наблюдатель останавливается; на `<html>` висит класс `vkt-tracklist-disabled`.
- Внутрь `contenteditable` и `textarea` кнопки не вставляются (защита от редактора поста).

## 10. Ограничения

- Всё завязано на разметку VK: `data-testid="post_text"`, `<br>`, абзацные `div` шириной 0. VK может её поменять.
- Комментарии не обрабатываются — только тексты постов.
- По умолчанию нужен аудио- или видеоролик в посте. Для чисто текстовых треклистов нужно снять галочку «Только посты с аудио или видео».
- Треклист должен быть либо нумерованным, либо с заголовком `Tracklist:` / `Треклист:` / `Playlist:`, либо блоком из 5+ строк «исполнитель — название».
- Поиск открывается на странице музыки; если ID не определён, первый клик может сначала открыть `/audios`, а затем расширение повторит переход с ID.
- Страница настроек и парсер проверены тестами, но не проходили живой прогон в Chrome в этой среде.

## 11. Если VK что-то поменял

Быстрый чек-лист:

1. Открыть пост, обновить вкладку (`F5`).
2. Проверить, что в посте есть аудио/видео и что расширение включено.
3. В DevTools проверить наличие `[data-testid="post_text"]` и `[data-testid="post"]`.
4. Посмотреть, чем разделены строки: `<br>` или `div` на строку. Для `div` парсер уже умеет блочные границы.
5. Проверить, что вложение имеет `data-testid` с `music`/`audio`/`video` (или это теги `audio`/`video`).
6. Если разметка изменилась — править `TEXT_SELECTOR`, `MEDIA_SELECTOR`, `POST_SELECTOR` и `breakAnchor` в `extension/content.js`.
7. Прогнать `node test/run-tests.mjs` и при необходимости добавить новый кейс в `test/fixture.html`.

Ключевые места в коде:

- `extension/content.js` — `extractLines`, `parseTrackLine`, `parseLooseTrack`, `collectUnnumberedTracks`, `buildSearchUrl`, `createButton`, `processTextElement`;
- `extension/common.js` — настройки по умолчанию;
- `extension/options.*` — настройки;
- `test/fixture.html` — эталонная разметка для тестов.
